# AI & Automation Stack — THE EXPAT NETWORK

## Purpose

This file defines how AI and automation tools may be used across THE EXPAT NETWORK.

The operating principle is:

> **AI tools are execution accelerators, not sources of truth.**

Canonical strategy, accepted ADRs, current official sources, compliance boundaries and human approval always outrank AI-generated output.

---

## 1. Authority hierarchy

Use this order whenever there is a conflict:

1. Current official / primary source
2. Current canonical TEN strategy files
3. Accepted ADRs
4. Current domain, workflow and product specifications
5. Source registry
6. Live implementation / current code
7. Latest research dossier
8. Legacy audits
9. AI-generated suggestions

No AI tool may silently override a higher-priority source.

---

## 2. Core execution stack

### ChatGPT — Strategy, research, orchestration and QA

**Status:** MVP NOW

Use ChatGPT for:
- strategy and information architecture;
- research synthesis;
- Germany pathway mapping;
- official-source verification workflows;
- SEO/content planning;
- homepage and tool specifications;
- WordPress/GitHub planning;
- partner/compliance review;
- LinkedIn and Instagram content development;
- QA and scope control.

ChatGPT must:
- verify current/high-stakes claims before publication;
- distinguish TEN explanation from official determination;
- respect `.org` / `.de` ownership;
- avoid inventing partnerships, statistics or outcomes.

---

### GitHub — Durable source of truth for code and project artefacts

**Status:** MVP NOW

Use GitHub for:
- canonical strategy/docs;
- ADRs;
- WordPress plugin source;
- `.de` tool source;
- version history;
- issues/backlog;
- pull requests;
- release notes;
- rollback references.

Never commit:
- API keys;
- passwords;
- WordPress/hosting credentials;
- personal lead data;
- CVs;
- residence/identity documents;
- health or banking data;
- tax identifiers;
- confidential partner contracts;
- private ERGO materials;
- internal commission schedules.

---

### Google Stitch — UI exploration and design accelerator

**Status:** MVP NOW

Use Stitch for:
- `.org` homepage UI concepts;
- pathway cards;
- profession/stage navigation;
- official-source components;
- organisation/cooperation components;
- `.de` tool-shell concepts;
- tool input/result screens;
- mobile variants.

Workflow:

Canonical spec
→ Stitch concepts
→ strategic/compliance review
→ approved direction
→ implementation

Stitch may suggest design, but may not define product strategy.

Do not accept automatically generated:
- dashboards;
- accounts;
- fake statistics;
- testimonials;
- partner logos;
- job marketplaces;
- unnecessary AI assistants.

---

### Google Antigravity — Engineering accelerator

**Status:** MVP NOW / NEXT

Use for:
- repository inspection;
- WordPress/PHP/JS/CSS changes;
- `.de` tool implementation;
- refactoring;
- automated testing;
- browser verification;
- preparing diffs / pull requests;
- regression checks.

Workflow:

Approved spec
→ GitHub issue
→ Antigravity implementation
→ tests
→ diff / PR
→ ChatGPT review
→ human approval
→ deployment

Do not expose production secrets or personal lead data.

## 3. Controlled experimentation tools

### Google AI Studio — AI prototyping laboratory

**Status:** NEXT

Use for controlled experiments such as:
- source-to-structured-data extraction;
- programme classification;
- profession/pathway classification;
- multilingual draft generation;
- public-source summarisation;
- structured JSON output;
- internal content/research assistants.

Do not use it to make final public determinations such as:
- visa eligibility;
- residence eligibility;
- recognition outcome;
- tax advice;
- insurance suitability;
- legal advice;
- candidate acceptance/rejection.

Where deterministic logic can solve the task reliably, prefer deterministic logic.

---

**Status:** NEXT / EXPERIMENT

- affected users;
- source date;
- `.org` pathway implication;
- `.de` tool implication;
- social-content angles;

#### Programme Intake Assistant

- public programme information

Output:
- organisation;
- eligible countries;
- professions;
- region;
- language;
- deadline;
- official link;
- last checked.

Human verification is mandatory before publication.

#### Competitor Monitor
Input:
- public competitor page/post

Output:
- positioning;
- audience;
- offer;
- monetisation;
- trust signals;
- strategic implication for TEN.

#### Social Research Converter
Input:
- verified source

Output:
- evidence;
- meaning;
- practical action;
- source;
- CTA options.

Opal is an internal operating tool unless a future use case is explicitly approved.

## 6. Prohibited AI use

Do not build or publish:

- AI auto-apply;
- AI job-application spam;
- AI visa decision engine;
- AI residence decision engine;
- AI recognition decision engine;
- AI insurance recommender outside authorised process;
- AI tax adviser;
- AI legal adviser;
- AI automatic candidate rejection;
- autonomous mass outreach;
- autonomous social publishing;
- fake testimonials or institutional claims;
- opaque AI scoring that materially affects people.

---

## 7. Human approval gates

Human review is required before:

- publishing legal/regulatory/high-stakes content;
- changing live WordPress code;
- merging production pull requests;
- publishing programme listings;
- naming a partner;
- sending personal data to a third party;
- publishing commercial/referral disclosures;
- publishing AI-generated social content representing people or institutions.

---

## 9. Scope-control rule

Before adding any AI or automation tool, answer:

1. What recurring problem does it solve?
2. Which TEN surface owns the outcome?
3. Does it reduce founder workload materially?
4. Can deterministic/simple tooling do the job better?
5. Does it introduce privacy, legal or trust risk?
6. Does it create a new dependency?
7. Is it MVP NOW, NEXT, LATER or DO NOT BUILD?

If the value is unclear, do not add it.
